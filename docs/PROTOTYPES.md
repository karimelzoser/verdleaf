# V2 prototype specification and acceptance
Open prototype/index.html locally (download raw file; no server required). This is an interactive visual study with original vector art, not photographs of Verdleaf, not production website. No external assets, real submissions or customer storage. Browser/device QA pending. All product-form/application examples illustrative. Production design needs original imagery and approved copy.
## Screen 1 — homepage
1440 desktop: asymmetrical hero split, large editorial headline, custom field illustration, vertical chapter marks, dual entry CTA, persistent buyer desk. 390 mobile: stack hero text before illustration, no horizontal scrolling, readable labels. Next chapter features product specimens, finder, field-to-shipment stage controls and journal placeholder with honest no-updates state. 
Motion: short fade/translate on entry and progressive botanical artwork, no autoplay or scroll locking. Product section visible without JS. Focus states and reduced motion.
## Screen 2 — product detail
Hibiscus example: form selector switches original schematic specimen, descriptive copy and request state. Show botanical name and public passport with unconfirmed values explicitly absent, illustrative application and packaging note. Use actual variant photos and scale comparison after assets. Add to shortlist, compare from product. No invented commercial parameters.
## Screen 3 — Buyer Desk
Anonymous buyer selects items and quantity, chooses per-item quote/sample/documents, reviews editable request, sees simulation only. Remove items and compare up to three. No personal details in design study. Production adds identity and server submission with receipt, safe attachment and outbox. 
## Review scenarios
1. On homepage, navigate to story then return to ingredient search within one action.
2. Search chamomile or botanical name; use application filter and no-results fallback.
3. Select hibiscus forms, observe image/label update and add variant to shortlist.
4. Add second product, open Buyer Desk, update kg, select sample and document intentions, remove item, review request; no data is sent.
5. Compare two or three items; prevent fourth and show honest unknown specs.
6. Keyboard tab through all controls, check labels/focus; check screen reader and reduced motion.
7. Visually review at 390/768/1024/1440 plus 320 width, zoom 200%; no overlap, overflow, clipping; validate native Arabic layout separately.
8. Production photography and claims sign-off; replace schematic artwork with original approved media as appropriate.
## Release gate
Prototype is not design-approved or browser-tested yet. Capture screenshots of every screen and key state, have procurement/quality/client reviewers complete tasks, record issues and iterate; then implement PHP/MySQL.
