# Hostinger deployment and release
No production deployment has been made. Confirm the actual subscription in hPanel before selecting an installation method. PHP 8.2+ with required Laravel extensions, Composer 2, MySQL/MariaDB, SSL, writable storage, cron and correct web root are required. PHP 8.3 was selected for CI. Node is needed only for optional browser tests; the public site uses server-rendered Blade and plain CSS/JS.
1. Create protected staging, separate DB and restricted DB user. Never reuse live WordPress database. Keep VERDLEAF_PREVIEW=true. On APP_ENV=production set VERDLEAF_PREVIEW_USER and VERDLEAF_PREVIEW_KEY (unique high entropy secret, HTTPS only); do not commit either.
2. Deploy reviewed commit and dependency lockfiles. composer install --no-dev --prefer-dist --optimize-autoloader. Create .env outside public web root, generate APP_KEY once, configure HTTPS APP_URL, database and mail. Preserve existing APP_KEY on subsequent deployments.
3. Point website document root to Laravel public/. If hosting cannot do this, use an approved layout that keeps app/bootstrap/config/vendor/storage/.env inaccessible or upgrade hosting. Never upload the project root as public_html.
4. php artisan migrate --force; php artisan db:seed only for initial draft catalogue; create administrator using php artisan verdleaf:admin EMAIL. Optional restricted roles via php artisan verdleaf:staff EMAIL editor|quality|sales|analytics.
5. Configure storage permissions and upload limits. Approved media and documents reside in private storage and are served by controlled routes. Verify backups include DB and storage; test restore. Set real SMTP and VERDLEAF_SALES_EMAIL. Set cron php artisan schedule:run every minute if plan supports it. Test both staff and buyer email in staging with authorized addresses. No production credentials in repository.
6. Import approved photos and actual product/crop/spec/certificate/exhibition/visit records; set hero approved image/video with poster and captions. Review rights and native Arabic. Verify every page visually and test forms, access controls, backups, privacy and SEO.
7. Capture existing site URL inventory, baseline Search Console and analytics. Map changed URLs in admin Growth; test redirects. Keep noindex and protected staging until client sign-off.
8. Take full live WordPress backup (database, files, media, config, redirects). Coordinate release window; deploy reviewed build, set APP_ENV=production, APP_DEBUG=false, VERDLEAF_PREVIEW=false only after verified content and legal/technical approval. Ensure secure cookies, HTTPS, mail, cron, health, 404s, redirects and sitemap. Submit sitemap to Search Console. No ranking promises.
9. Rollback: restore previous document root/site, DB and media snapshot as appropriate; retain new enquiry data securely if any; do not blindly roll back data. Record release SHA and operator. Monitor errors, form failures and organic traffic.
